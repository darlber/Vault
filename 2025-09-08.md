# Commit 1
Refactor: Improve TimerService broadcast and TimerBar layout  
  
This commit introduces improvements to the `TimerService` broadcast mechanism and refactors the `TimerBar` layout for better responsiveness.  
  
**Key Changes:**  
  
- **`TimerService.kt`:**  
    - The `sendStatus` broadcast intent is now made explicit by setting the package name (`it.setPackage(packageName)`). This is a recommended practice for security and to ensure the broadcast is received only by the intended application component, especially on newer Android versions.  
    - Added more detailed Timber logging for broadcasting status.  
  
- **`Session.kt`:**  
    - In the `BroadcastReceiver` for `TimerService.Intents.STATUS`:  
        - Added detailed Timber logging to trace received broadcast intents and their extras.  
        - When extracting extras (`TIME`, `MAX_TIME`), a default value of `-1L` is now used to distinguish between a missing extra and an actual value of `0L`.  
        - The `timerState.value` is updated to revert these `-1L` defaults back to `0L` if the keys were actually missing, ensuring `TimerState` always holds valid non-negative time values.  
        - Handles the case where the received intent itself might be null.  
  
- **`TimerBar.kt`:**  
    - The `TimerBar` composable is now wrapped in a `BoxWithConstraints`.  
    - The `timerWidth` (the width of the progress indicator `Surface`) is now calculated using `maxWidth` from `BoxWithConstraintsScope` instead of `LocalWindowInfo.current.containerSize.width.dp`. This makes the `timerWidth` calculation more robust and directly tied to the available width of the `TimerBar` itself, rather than the entire screen.  
    - Added `@SuppressLint("UnusedBoxWithConstraintsScope")` as the `constraints` object isn't directly used beyond `maxWidth`.  
  
**Impact:**  
  
- Improves the reliability and security of `TimerService` broadcasts by making them explicit.  
- Enhances debuggability of timer state updates in `Session.kt` through more detailed logging.  
- Makes the `TimerBar` progress indicator width calculation more accurate and responsive to its parent's constraints.
# Commit 2
Refactor: Rename project from ExerLog to MysLog  
  
This commit renames the project from "ExerLog" to "MysLog" across all relevant files and configurations.  
  
**Key Changes:**  
  
- **Package Names:** All package names changed from `com.example.exerlog` to `com.example.myslog`.  
- **Application ID:** Updated in `app/build.gradle.kts` from `com.example.exerlog` to `com.example.myslog`.  
- **Root Project Name:** Changed in `settings.gradle.kts` from "ExerLog" to "MysLog".  
- **Class Names:**  
    - `ExerLogApp` renamed to `MysLogApp`.  
    - `ExerDAO` renamed to `MysDAO`.  
    - `ExerRepository` renamed to `MysRepository`.  
    - `ExerRepositoryImpl` renamed to `MysRepositoryImpl`.  
- **String Resources:** `app_name` in `strings.xml` and `values-es/strings.xml` updated from "ExerLog" to "MysLog".  
- **Theme Names:** Theme names in `themes.xml` updated from `Theme.ExerLog` to `Theme.MysLogApp`.  
- **Database Name Constant:** `DATABASE_NAME` in `Constants.kt` changed from `"exerlog_db"` to `"mys_db"`.  
- **Author Constant:** `APP_AUTHOR` in `Constants.kt` updated from `"Your Name"` to `"Darlber"`.  
- **File Renames:** Numerous files were renamed to reflect the new project name and package structure (e.g., `ExerLogApp.kt` to `MysLogApp.kt`, `ExerDAO.kt` to `MysDAO.kt`, etc.).  
- **Import Statements:** All import statements updated to reflect the new package names.  
- **Android Manifest:**  
    - `android:name` for the application tag updated to `.MysLogApp`.  
    - `android:label` for the application tag updated to `@string/app_name` (which now resolves to "MysLog").  
    - `android:theme` for the activity tag updated to `@style/Theme.MysLogApp.Splash`.  
- **Build Files:** Namespace and application ID updated in `app/build.gradle.kts`.  
- **IDE Configuration:** Deployment target selector timestamp updated.  
- **Test Files:** Package names in test files (`ExampleUnitTest.kt`, `ExampleInstrumentedTest.kt`) updated.  
- **TimerService:**  
    - When broadcasting status, the intent package is now explicitly set using `it.setPackage(packageName)` to ensure it's an explicit intent. This is a good practice for security and reliability, especially on newer Android versions.  
    - Added more detailed Timber logging for received broadcast data in `Session.kt` to aid in debugging timer state updates.  
- **TimerBar.kt:**  
    - Now uses `BoxWithConstraints` to determine `maxWidth` for calculating `timerWidth`, making it more robust than relying on `LocalWindowInfo`. The `LocalWindowInfo` approach was removed.  
    - Added `@SuppressLint("UnusedBoxWithConstraintsScope")` as the constraints are used directly.  
- **Removed Unused Files:**  
    - `app/src/main/java/com/example/exerlog/core/Equipment.kt`  
    - `app/src/main/java/com/example/exerlog/utils/Event.kt` (an identical file was re-added under the new package structure)  
    - `app/src/main/java/com/example/exerlog/core/MuscleGroup.kt`  
  
**Impact:**  
- Standardizes the project naming to "MysLog".  
- Ensures consistency across the codebase and configuration files.  
- Improves TimerService broadcast reliability and debuggability.  
- Makes TimerBar width calculation more robust.
