# Commit Final
Refactor: Improve TimerService broadcast and TimerBar layout  
  
This commit introduces improvements to the `TimerService` broadcast mechanism and refactors the `TimerBar` layout for better responsiveness.  
  
**Key Changes:**  
  
- **`TimerService.kt`:**  
    - The `sendStatus` broadcast intent is now made explicit by setting the package name (`it.setPackage(packageName)`). This is a recommended practice for security and to ensure the broadcast is received only by the intended application component, especially on newer Android versions.  
    - Added more detailed Timber logging for broadcasting status.  
  
- **`Session.kt`:**  
    - In the `BroadcastReceiver` for `TimerService.Intents.STATUS`:  
        - Added detailed Timber logging to trace received broadcast intents and their extras.  
        - When extracting extras (`TIME`, `MAX_TIME`), a default value of `-1L` is now used to distinguish between a missing extra and an actual value of `0L`.  
        - The `timerState.value` is updated to revert these `-1L` defaults back to `0L` if the keys were actually missing, ensuring `TimerState` always holds valid non-negative time values.  
        - Handles the case where the received intent itself might be null.  
  
- **`TimerBar.kt`:**  
    - The `TimerBar` composable is now wrapped in a `BoxWithConstraints`.  
    - The `timerWidth` (the width of the progress indicator `Surface`) is now calculated using `maxWidth` from `BoxWithConstraintsScope` instead of `LocalWindowInfo.current.containerSize.width.dp`. This makes the `timerWidth` calculation more robust and directly tied to the available width of the `TimerBar` itself, rather than the entire screen.  
    - Added `@SuppressLint("UnusedBoxWithConstraintsScope")` as the `constraints` object isn't directly used beyond `maxWidth`.  
  
**Impact:**  
  
- Improves the reliability and security of `TimerService` broadcasts by making them explicit.  
- Enhances debuggability of timer state updates in `Session.kt` through more detailed logging.  
- Makes the `TimerBar` progress indicator width calculation more accurate and responsive to its parent's constraints.
