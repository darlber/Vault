# MuscleSheet
```kotlin
package com.example.exerlog.ui.exercisepicker.components  
  
import androidx.compose.runtime.Composable  
  
import com.example.exerlog.ui.exercisepicker.ExerciseEvent  
import com.example.exerlog.utils.Event  
  
  
@Composable  
fun MuscleSheet(  
  selectedMusclegroups: List<String>,  
  allMuscleGroups:() -> List<String>,  
  onEvent: (Event) -> Unit  
) {  
  Sheet(  
    items = allMuscleGroups().sorted(),  
    selectedItems = selectedMusclegroups,  
    title = "Filter by Body-part",  
    onSelect = { onEvent(ExerciseEvent.SelectMuscle(it)) }  
  ) {  
    onEvent(ExerciseEvent.DeselectMuscles)  
  }  
}
```

# Commit Final
Refactor: Update ExercisePicker to use official Material3 ModalBottomSheet  
  
This commit replaces the custom `ModalBottomSheetLayout` implementation with the official `ModalBottomSheet` from Material 3. It also updates the data source for muscle and equipment filters in the `ExercisePickerScreen` to fetch directly from the database.  
  
**Key Changes:**  
  
- **`ModalBottomSheet.kt`, `Strings.kt`, `Swipeable.kt` (in `ui/modalbottomsheet`):**  
    - Removed custom modal bottom sheet implementation files.  
- **`ExercisePicker.kt`:**  
    - Replaced `com.example.exerlog.ui.modalbottomsheet.ModalBottomSheetLayout` with `androidx.compose.material3.ModalBottomSheet`.  
    - Updated `rememberModalBottomSheetState` usage to the official Material 3 version, setting `skipPartiallyExpanded = true`.  
    - `EquipmentSheet` and `MuscleSheet` are now displayed within the official `ModalBottomSheet` when `sheetState.isVisible` is true.  
    - `_allEquipment` in `ExerciseViewModel` is now populated from `repo.getAllEquipment()`.  
    - Added `_allMuscles` StateFlow to `ExerciseViewModel`, populated from `repo.getAllMuscles()`.  
    - `MuscleSheet` now receives `allMuscleGroups` from `_allMuscles`.  
- **`ExerciseViewModel.kt`:**  
    - Added `_allMuscles` StateFlow to hold the list of all available primary muscles fetched from the repository.  
    - Initialized `_allMuscles` by collecting from `repo.getAllMuscles()`.  
    - The filtering logic for `filteredExercises` now considers primary and secondary muscles. (TODO: Review if secondary muscles should be included).  
- **`MuscleSheet.kt`:**  
    - Now accepts `allMuscleGroups: List<String>` as a parameter to display all available muscles for filtering.  
- **`ExercisePickerPreview.kt`:**  
    - Swapped the click handlers for muscle and equipment filter chips to ensure correct bottom sheet content is shown.  
    - Changed `horizontalArrangement` in the filter chip row to `Arrangement.SpaceEvenly`.  
- **`ExerDAO.kt`:**  
    - Added `getAllMuscles(): Flow<List<String>>` to retrieve distinct primary muscles from the `EXERCISE` table.  
    - Modified `getAllEquipment()` query to filter out NULL equipment values.  
- **`ExerRepository.kt` & `ExerRepositoryImpl.kt`:**  
    - Added `getAllMuscles()` to the interface and implementation, delegating to `dao.getAllMuscles()`.  
- **`Converters.kt`:**  
    - Improved `fromString` to handle null or blank input, returning an empty list.  
    - Improved `fromList` to handle null input, returning an empty string.  
    - `toDateTime` now returns `null` if the source string is null or blank.  
- **`Entities.kt`:**  
    - Added `EQUIPMENT` and `PRIMARYMUSCLE` constants for table column names.  
  
**Impact:**  
  
- Simplifies the codebase by removing custom bottom sheet components and leveraging the official Material 3 library.  
- Ensures that muscle and equipment filters in the `ExercisePickerScreen` are dynamically populated with data from the database, providing a more accurate and up-to-date filtering experience.  
- Improves robustness of `TypeConverter` methods.
