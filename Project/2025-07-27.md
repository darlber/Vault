# Commit Final
## 1a Parte
Feat: Implement HomeViewModel and initial session logic  
  
This commit introduces the `HomeViewModel` to manage the home screen's state and logic. It also includes initial setup for session handling and database pre-population.  
  
**Key Changes:**  
  
- **`HomeViewModel.kt`:**  
    - Manages the list of sessions (`SessionWrapper`) by combining data from `getAllSessionExercises` and `getAllSessions` from the repository.  
    - Handles UI events (`HomeEvent`) such as:  
        - `SessionClicked`: Navigates to the session details screen.  
        - `NewSession`: Creates a new session and navigates to it.  
        - `OpenSettings`: Navigates to the settings screen.  
    - Uses `Flow` and `StateFlow` for reactive data updates.  
- **`Home.kt`:**  
    - Integrated `HomeViewModel` using `hiltViewModel()`.  
    - `sessions` are now collected from the ViewModel's `StateFlow`.  
    - Navigation events are handled by observing `viewModel.uiEvent`.  
    - Bottom bar actions (`onAddClick`, `onSettingsClick`) are now delegated to `viewModel.onEvent`.  
    - Removed dummy data and previews.  
- **`HomeEvent.kt`:**  
    - Defined sealed class `HomeEvent` for home screen actions: `SessionClicked`, `NewSession`, `OpenSettings`.  
- **Database (`ExerDAO.kt`, `PopulateDatabaseCallback.kt`):**  
    - `ExerDAO`: Added `insertAll(exercises: List<Exercise>)` for batch insertion. `getAllExercises` now orders by `name`. `getMuscleGroupsForSession` now queries `primaryMuscles`.  
    - `PopulateDatabaseCallback.kt`: New class to pre-populate the database with exercises from a JSON file (`R.raw.exercises`) on creation. Uses Gson for parsing.  
- **Repository (`ExerRepositoryImpl.kt`):**  
    - Annotated with `@Singleton` and `@Inject constructor` for Hilt dependency injection.  
- **`MainActivity.kt`:**  
    - Implemented full-screen mode by hiding system bars.  
    - Injected `ExerDAO` (though not yet used directly in this commit).  
- **Gradle:**  
    - Added `com.google.code.gson:gson` dependency for JSON parsing.  
- **Removed:**  
    - `di/TODO.kt` file.  
- **New Placeholder Files:**  
    - `ui/session/SessionEvent.kt`  
    - `ui/session/SessionViewModel.kt`  
    - `ui/session/Session.kt` (likely a Composable screen for session details)  
  
**Impact:**  
  
- Establishes a reactive UI for the home screen powered by `ViewModel` and `Flow`.  
- Enables basic session creation and navigation.  
- Automates database initialization with a predefined set of exercises.  
- Improves code structure with dedicated event classes and dependency injection.

Refactor: Update Exercise entity and integrate Hilt for database  
  
This commit refactors the `Exercise` entity and integrates Hilt for database dependency injection.  
## 2a Parte
**Key Changes:**  
  
- **`Exercise.kt`:**  
    - Updated the `Exercise` entity fields to reflect a more structured exercise definition:  
        - `id` is now a `String` (likely a unique identifier from a predefined dataset).  
        - Added `name`, `level`, `mechanic`, `instructions`, `category`, and `images`.  
        - `force` and `equipment` are now single `String?` values instead of lists.  
        - Renamed `targets` to `primaryMuscles` and `synergists` to `secondaryMuscles`.  
        - Removed `title`, `type`, and `stabilizers`.  
    - Commented out `getMuscleGroups` and `getStringMatch` methods.  
- **`DatabaseModule.kt` (New File):**  
    - Introduced a Hilt module (`@Module`, `@InstallIn(SingletonComponent::class)`) to provide database-related dependencies.  
    - Provides `GymDatabase` as a singleton, using `PopulateDatabaseCallback` for initial data.  
    - Provides `ExerDAO`.  
    - Provides `ExerRepositoryImpl` as the implementation for `ExerRepository`.  
    - Includes Timber logging for database creation and DAO provision.  
- **`Constants.kt` (New File):**  
    - Added a `Constants` class to store application-wide constants:  
        - `DATABASE_NAME`  
        - `EXERCISES_NAME` (for the JSON file used in `PopulateDatabaseCallback`)  
        - `APP_VERSION`  
        - `APP_AUTHOR`  
- **`ExerciseExtension.kt` (New File):**  
    - Added an extension function `sortedListOfMuscleGroups()` for `List<Exercise>`. This function flattens `primaryMuscles` and `secondaryMuscles` from all exercises, counts the occurrences of each muscle group, and returns a sorted list of muscle group names by frequency.  
- **`build.gradle.kts`:**  
    - Removed `annotationProcessor(libs.androidx.room.compiler)` as KSP is used.  
    - Added `implementation(libs.gson)` dependency for JSON parsing (likely used by `PopulateDatabaseCallback`).  
  
**Impact:**  
  
- Standardizes the structure of the `Exercise` entity.  
- Enables dependency injection for database components using Hilt, improving testability and code organization.  
- Centralizes application constants.  
- Provides a utility function for analyzing muscle group usage across exercises.
