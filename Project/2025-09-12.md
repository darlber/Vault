# Commit Final

Refactor: Improve language change logging and database clearing  
  
This commit enhances logging during language changes in the `ExercisePicker` and `ExerciseViewModel`, and modifies the database clearing mechanism.  
  
**Key Changes:**  
  
- **`ExercisePicker.kt`:**  
    - Added `Timber.d("Device language: $currentDeviceLang")` to log the detected device language when the `LaunchedEffect` for language change is triggered.  
- **`ExerciseViewModel.kt`:**  
    - Added `Timber.d("Language changed to $lang")` within the `changeLanguage` function to log when the repository's language switch is invoked.  
- **`MysRepositoryImpl.kt`:**  
    - `clearDatabaseInternal()`:  
        - Changed logging from "Clearing database" to "Clearing exercises".  
        - Now only calls `dao.clearExercises()` instead of `db.clearAllTables()` and `dao.deletePrimaryKeyIndex()`. This is a more targeted approach if the intent is only to clear exercise-specific data.  
  
**Minor Changes:**  
- **`.idea/deploymentTargetSelector.xml`:** Updated the selected deployment target timestamp and device.  
- **`app/src/main/java/com/example/myslog/ui/session/Session.kt`:** Added `@Preview` annotation import, though no preview function was added in this diff.  
  
**Impact:**  
- Provides better debug information regarding language detection and switching.  
- Modifies the database clearing behavior to be more specific to exercises, which might be intended if other tables should persist. If a full database clear was intended, this change might need review.
# Commit Final 2
Refactor: Add Workout entities and filtering to ExercisePicker  
  
This commit introduces `Workout` and `WorkoutExercise` entities to the database, allowing users to create and manage workouts (collections of exercises). The `ExercisePicker` UI has been updated to filter exercises by these workouts.  
  
**Key Changes:**  
  
- **Database & Entities:**  
    - `Database.kt`: Added `Workout::class` and `WorkoutExercise::class` to the list of entities. Database version incremented to 3.  
    - `Workout.kt` (New Entity): Defines a workout with an `id` and `name`.  
    - `WorkoutExercise.kt` (New Entity): Links exercises (`exerciseId`) to a parent workout (`parentWorkoutId`).  
    - `MysDAO.kt`:  
        - Added `insertWorkout(Workout)` and `insertWorkoutExercise(WorkoutExercise)`.  
        - Added `getAllWorkouts(): Flow<List<Workout>>`.  
        - Added `getExercisesForWorkout(workoutId: Long): Flow<List<WorkoutExercise>>`.  
        - Added `deleteWorkout(Workout)` and `deleteWorkoutById(workoutId: Long)`.  
    - `core/Entities.kt`: Added `WORKOUT` and `WORKOUTEXERCISE` constants.  
  
- **Repository:**  
    - `MysRepository.kt` & `MysRepositoryImpl.kt`:  
        - Implemented corresponding functions for the new DAO methods related to workouts (insert, get all, get exercises for workout, delete).  
  
- **ExercisePicker & ViewModel:**  
    - `ExerciseViewModel.kt`:  
        - Added `_workoutFilter: MutableStateFlow<List<Long>>` to store selected workout IDs for filtering.  
        - Added `_allWorkouts: MutableStateFlow<List<Workout>>` to store all available workouts.  
        - Modified `filteredExercises` combine logic to include `workoutCondition`: filters exercises based on whether they belong to any of the selected workouts.  
        - Added new `ExerciseEvent`s:  
            - `SelectWorkout(workoutId: Long)`: Toggles selection of a workout for filtering.  
            - `DeselectWorkouts`: Clears the workout filter.  
            - `AddWorkout(workoutName: String)`: Creates a new workout with the currently selected exercises.  
        - `onEvent`: Handles new workout-related events, updating `_workoutFilter` and inserting new workouts/workout_exercises into the database.  
        - Fetches all workouts in `init`.  
    - `ExercisePicker.kt`:  
        - Passes `workoutFilter` and `allWorkouts` state to `ExercisePickerPreview`.  
        - Removed the Material3 `ModalBottomSheet` and related states (`sheetState`, `equipmentBottomsheet`) for muscle/equipment filtering, as this functionality is now handled differently or temporarily removed from this specific screen. (The `onMuscleFilterClick` and `onEquipmentFilterClick` lambdas are now empty).  
    - `ExercisePickerPreview.kt`:  
        - Added `workoutFilter: List<Long>` and `allWorkouts: List<Workout>` parameters.  
        - Added a "Workout" `FilterChip` that, when clicked, toggles `showWorkoutDropdown`.  
        - Added an `AnimatedVisibility` section for `showWorkoutDropdown`:  
            - Includes an `OutlinedTextField` to input a `newWorkoutName`.  
            - A "Añadir" (Add) `Button` to create a new workout using `ExerciseEvent.AddWorkout`.  
            - Displays a list of `allWorkouts` with `Checkbox`es to select/deselect them for filtering, triggering `ExerciseEvent.SelectWorkout`.  
        - Removed `showWorkoutNameDialog` and its related `AlertDialog`, as adding workouts is now handled within the dropdown.  
    - `ExerciseEvent.kt`:  
        - Added `SaveWorkout`, `SelectWorkout`, `DeselectWorkouts`, `AddWorkout` events.  
  
- **Minor:**  
    - `SettingsEvent.kt`: No functional change, just reformatting.  
    - `.idea/copilot.data.migration.agent.xml` and `.idea/copilot.data.migration.edit.xml`: New IDE configuration files, likely related to GitHub Copilot settings.  
    - `.idea/.name`: New file specifying project name as "MysLog".  
  
**Impact:**  
  
- Users can now group exercises into custom workouts.  
- The `ExercisePicker` allows users to filter the exercise list by one or more selected workouts.  
- The UI for muscle and equipment filtering in `ExercisePicker` has been removed or will be re-implemented.  
- Database schema has been updated to support workout functionality.
